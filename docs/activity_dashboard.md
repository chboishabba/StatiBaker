# Activity Dashboard (Process Lens)

This dashboard is a read-only process lens over SB artifacts.

Implementation/reproduction detail is documented in
`docs/dashboard_implementation_notes.md`.

It exists to answer:
- What activity was observed and synchronized for the day?
- How often did chat, shell, and interaction signals occur?
- Which process documents summarize or contextualize that activity?

## Scope

The dashboard integrates:
- chat activity (frequency, thread counts, timeline events)
- tool-use extraction from chat `tool` messages (command families, variants,
  repeat counts, and directories touched)
  - `rg` commands are additionally grouped by mode (`--files`, `-n`, other)
    with per-mode variant diffs to avoid repeating full command prefixes
- git branch history events (checkout/create/rename/merge/tip updates)
- PR lifecycle events (received/opened/commented/reviewed/merged/closed)
- CLI metadata events (command hash, exit, duration)
- input activity (key/mouse counts only)
- window focus metadata (app id, title hash, duration)
- SB activity events (`activity_ledger.json`)
- notes metadata lifecycle (`logs/notes/<date>.jsonl`)
  - NotebookLM lifecycle counters: notebook/file created, modified, moved/renamed, deleted, seen
- media consumption metadata (`logs/media/<date>.jsonl`)
  - watch/listen seconds, completion ratio, churn events/rate
- generated SB summaries (`daily_brief.md`, `retrospective.md`, `state.json`, `drift.json`)

## Data sources (default)

- `runs/<date>/logs/*/*.jsonl`
- `runs/<date>/logs/git_branch/<date>.jsonl`
- `runs/<date>/logs/pr/<date>.jsonl`
- `runs/<date>/outputs/activity_ledger.json`
- `runs/<date>/outputs/daily_brief.md`
- `runs/<date>/outputs/retrospective.md`
- `runs/<date>/outputs/state.json`
- `runs/<date>/outputs/drift.json`
- `~/.chat_archive.sqlite` (preferred chat source)
- `chat_exports/*.json` (chat fallback)
- `__CONTEXT/convo_ids.md` (thread scope)
- `__CONTEXT/last_sync/*` (process-context links)

## Outputs

- Canonical (DB):
  - `SB_RUNS_ROOT/dashboard.sqlite` (default) containing daily/weekly/lifetime dashboards
    and their component tables (timeline, frequency_by_hour, artifact_links, etc).
- Optional legacy exports (regression/debug only):
  - `runs/<date>/outputs/dashboard*.json`
  - `runs/<date>/outputs/dashboard*.html`

**Policy:** dashboards are stored canonically in the DB. JSON/HTML files are treated
as legacy exports (useful for regression tests and ad-hoc inspection), not the
source of truth.

## UI availability

Yes. The dashboard UI can be served by `itir-svelte` (DB-hydrated) and can also be
exported as static HTML for portability:

- `runs/<date>/outputs/dashboard.html`

The HTML export is generated by `scripts/build_dashboard.py` and links process artifacts plus
timeline/histogram views.

Timeline filters are optional and client-side:
- kind (chat/shell/input/window/git/git_branch/pr/activity)
- source class (sqlite/chat exports/resolver/logs/activity/outputs)
- chat role (user/assistant/tool/etc)
- free-text search over rendered timeline details

Untitled chat threads are automatically labeled from first user-message preview
and tagged with an origin class (for example `codex-ingest` when sqlite
`source_id` starts with `codex_`).

Timeline strip palette controls are client-side and include:
- `Viridis` (default)
- `Turbo (Rainbow)`
- `Plasma (Blue-Pink-Yellow)`
- `RdYlGn (Red-Yellow-Green)`
- `Custom` comma-separated CSS colors (persisted in browser local storage)

Timeline strip color algorithm controls are also client-side:
- `Thread`
- `Time of Day`
- `Chat Role`
- `Switch vs Stay`

## Chat flow view modes

Current default:
- `Chat Flow Timeline Strip` (linear, time-scaled sequence).

Planned alternate:
- `Thread Lanes` (true lane chart with cross-lane connectors).

Design and rollout details:
- `docs/chat_flow_lane_mode.md`

Dense-day behavior target:
- keep strip mode as fallback for high message/thread counts,
- use lane mode when visual complexity remains manageable.

NotebookLM metadata section:
- Daily dashboard includes a `NotebookLM Lifecycle (Metadata)` panel.
- Weekly and lifetime dashboards include aggregated notebook/file lifecycle totals.
- `seen` reflects snapshot/observed rows (for example `notebook_observed`, `source_observed`).

Context/cost estimate section:
- Daily dashboard includes per-thread context usage approximation
  (`chars -> tokens` heuristic) and overflow indicators.
- Lifetime mode emits a dedicated indicative costing page
  (`dashboard_costing(.html|.json)`).
- Costing output is scenario-based and non-authoritative; it is not invoice truth.

## Build command

```bash
python scripts/build_dashboard.py --date 2026-02-08
```

Debug mode (chat full-scan for the day, ignoring `convo_ids` scope):

```bash
python scripts/build_dashboard.py --date 2026-02-08 --debug
```

Weekly summary mode (aggregates daily summaries over a rolling window ending at
`--date`):

```bash
python scripts/build_dashboard.py --date 2026-02-08 --weekly --weekly-days 7
```

## Real data vs fallback data in `run_day.sh`

- Always real (if available): git commits (`adapters/gitlog.py`) and git branch
  events (`adapters/git_branch.py`) from the target repo/date.
- Real when provided: input/window/CLI/AV/browser/cloud/notes/social/system/PR
  logs from passed file paths.
- Real when available and configured: Prometheus and osquery collectors.
- Synthetic fallback: if `SNAPSHOTS_PATH` is omitted and
  `tests/fixtures/snapshots.json` exists, sessionizer uses that fixture.
- Direct PR connector requires `gh`; if it fails, state is labeled
  `pr_events_missing`.

## Direct PR connector

GitHub PR events can be collected directly with:

```bash
python adapters/pr_events_github.py --date 2026-02-08 --repo owner/repo --output /tmp/pr_events.jsonl
```

Or via `run_day.sh` using positional argument 19:

```bash
./scripts/run_day.sh 2026-02-08 . "" "" "" "" "" "" "" "" "" "" "" "" "" "" "" "" auto
```

Use `auto` to derive repo from `git remote origin`, or pass `owner/repo`.

## Invariants

- Read-only: dashboard generation must not mutate SB state artifacts.
- Meta-first: shell/input/window records remain metadata; no raw command text or window titles are required.
- Explicit provenance: timeline items include source file paths.
- Timeline readability: long detail text is folded by default and expandable on
  demand; source path is preserved via hover tooltip on source badges.
- Sync outcomes are state: partial and failed sync paths are surfaced as warnings, not hidden.
- Process-doc linkage: context/sync artifacts are linked as references, not promoted into state.
- Deterministic output for fixed inputs.
- Default chat scope is opt-in via `convo_ids`; debug mode may disable scope for diagnostics.

## Non-goals

- Not an orchestration plane.
- Not an agent control surface.
- Not a semantic interpreter of chat or source content.
